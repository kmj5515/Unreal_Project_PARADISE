# Development Roadmap

## Phase 1 – 기본 프로젝트 / 멀티 세팅 (1주차)
- [x] UE5 프로젝트 생성 및 소스 세팅 (C++ 프로젝트, Git 연동)
- [x] 에디터/엔진 버전 고정 및 `DefaultEngine.ini` 기본 네트워크 설정
- [x] 멀티플레이 활성화 (Listen 서버, 다중 PIE 클라이언트 테스트 가능 상태)
- [x] 기본 `GameMode`, `GameState`, `PlayerState`, `PlayerController` 생성
- [x] 시작 맵 / 테스트 맵 분리 및 게임 모드 매핑

## Phase 2 – 기본 캐릭터 움직임 (이동/점프/웅크리기) (1–2주차)
- [x] `AParadiseCharacterBase` 구현 (캡슐, 메쉬, MovementComponent 세팅)
- [x] Enhanced Input 적용 (Input Mapping Context, Input Action)
- [x] 기본 이동(WSAD), 마우스 Look, 점프 구현
- [ ] 웅크리기(Crouch) 상태 구현 (속도 감소, 캡슐 높이 변경)
- [ ] 스프린트(Shift) 등 간단한 이동 상태 추가
- [x] 캐릭터 이동/상태 복제(Replication) 적용 및 멀티 환경에서 검증

## Phase 3 – 기본 애니메이션 (이동/점프) (2–3주차)
- [x] 캐릭터용 스켈레탈 메쉬/애니메이션 리소스 연결
- [x] 기본 AnimInstance / AnimBlueprint 생성
- [x] 이동 애니메이션 (Idle/Walk/Run) 블렌드 스페이스 세팅
- [x] 점프/낙하/착지 애니메이션 상태 추가
- [x] C++ AnimInstance에서 `GroundSpeed`, `IsFalling`, `ShouldMove`, `Velocity` 계산
- [x] 멀티 환경에서 애니메이션 재생 동기화 확인

## Phase 4 – 캐릭터 커스터마이징 & 로비 화면 (3–4주차)
- [ ] 캐릭터 커스터마이징용 전용 맵/씬 구성 (가운데 캐릭터 1명 표시)
- [ ] 커스터마이징 가능한 아이템/슬롯 설계 (상의, 하의, 헤드, 무기 스킨 등 최소 단위)
- [ ] 커스터마이징 데이터 구조 설계 (ID, Mesh, Material, Preview 등)
- [ ] 로컬/서버에 커스터마이징 선택 정보 저장 구조 설계 (`PlayerState` 또는 SaveGame)
- [ ] 커스터마이징 UI 구현 (아이템 리스트, 선택, 미리보기)
- [ ] 선택된 커스터마이징을 인게임 캐릭터 스폰 시 적용

## Phase 5 – 인게임 맵 구성 & 파쿠르 베이스 (4–5주차)
- [ ] 첫 번째 인게임 맵 구성 (건물, 담장, 장애물 등 간단한 레벨 블록아웃)
- [ ] 이동/점프/웅크리기를 활용할 수 있는 레이아웃 배치
- [ ] 간단한 파쿠르/지형 인터랙션 후보 정의 (담 넘기, 난간 오르기 등)
- [ ] 필요한 경우 파쿠르용 트리거 박스/볼륨 설계 (후에 시스템 확장 여지 확보)
- [ ] NavMesh, 조명, 기본 퍼포먼스 프로파일링

## Phase 6 – 무기 시스템 (단검, 망치, 총) (5–6주차)
- [ ] 무기 베이스 클래스 설계 (`AWeaponBase`)
- [ ] 근접 무기 서브클래스 (단검, 망치) 구현
- [ ] 원거리 무기 서브클래스 (권총/라이플 등 총기 1종) 구현
- [ ] 캐릭터 무기 장착/해제 시스템 구현 (소켓 부착, 장착 상태 복제)
- [ ] 근접 무기 공격(스윙) 로직 및 히트 판정(Trace/Overlap) 구현
- [ ] 총기 발사 로직 (히트스캔 또는 프로젝타일) 및 탄약 시스템 기본 구현
- [ ] 멀티플레이 환경에서 무기 장착/발사/공격 애니메이션 복제 확인

## Phase 7 – Gameplay Ability System Core & 데미지/체력 (6–7주차)
- [ ] GAS 모듈 프로젝트에 추가 및 빌드 설정
- [ ] 플레이어용 `AbilitySystemComponent` / `AttributeSet` 구현
- [ ] 핵심 어트리뷰트 정의 (Health, Stamina, Damage, Armor 등)
- [ ] 데미지/힐/스태미나용 `GameplayEffect` 구현
- [ ] 무기/공격 로직을 GAS와 연동 (공격 시 `GameplayEffect` 적용)
- [ ] 사망 처리 로직 (Health <= 0, 죽음 상태, 리스폰 훅) 구현
- [ ] 멀티 환경에서 데미지/체력/사망 상태가 정확히 복제되는지 검증

## Phase 8 – 인벤토리 & 아이템 줍기/버리기 (7–8주차)
- [ ] `UInventoryComponent` 설계 및 캐릭터에 부착
- [ ] 아이템 데이터 구조 정의 (ID, 타입, 스택, 무게, 장비 가능 슬롯 등)
- [ ] 월드 아이템 액터 구현 (루팅 가능한 오브젝트, 떨어진 무기/아이템)
- [ ] 라인트레이스/오버랩 기반 상호작용으로 아이템 줍기 구현 (서버 권한)
- [ ] 인벤토리에서 아이템 버리기 → 월드 아이템 스폰 로직 구현
- [ ] 인벤토리 상태 복제 및 클라이언트 UI 동기화
- [ ] 장비 슬롯과 무기 시스템 연동 (인벤토리 변경 → 장착 상태 반영)

## Phase 9 – 맵 인터랙션 (철문, 자동차 사이렌 등) (8–9주차)
- [ ] 공통 상호작용 인터페이스(`UInterface`) 구현 (문, 레버, 버튼 등)
- [ ] 철문 액터 구현 (열기/닫기, 잠금 상태, 사운드/애니메이션)
- [ ] 자동차 사이렌 액터 구현 (켜기/끄기, 소리/빛 효과)
- [ ] 인터랙션 입력(Interact)과 월드 액터 연동 (서버 권한 처리, 상태 복제)
- [ ] 인터랙션 상태(열림/닫힘, On/Off) 복제 및 클라이언트 동기화 검증
- [ ] 맵 상에 배치하여 게임플레이 플로우(은폐, 어그로, 경보 등)에 활용

## Phase 10 – Zombie AI (PvE) (9–10주차)
- [ ] 좀비 캐릭터/메쉬/애니메이션 세팅
- [ ] 좀비용 AIController 및 Behavior Tree 구현 (순찰, 소리/시야 탐지, 추격, 공격)
- [ ] Perception 시스템 설정 (시야/청각으로 플레이어 및 소음 탐지)
- [ ] 좀비 공격을 GAS 어빌리티/GameplayEffect로 구현 (데미지, 상태 이상 등)
- [ ] 좀비 피격/사망 처리 (애니메이션, 래그돌/디스폰)
- [ ] 스폰 시스템 구현 (스포너, 웨이브/지역 기반) 및 난이도 조정
- [ ] 멀티 환경에서 AI 동작/공격/데미지가 정확히 복제되는지 검증

## Phase 11 – UI & 기본 게임 루프 정리 (10–11주차)
- [ ] HUD 구현 (체력, 스태미나, 현재 무기/탄약, 인터랙션 프롬프트)
- [ ] 인벤토리 UI 구현 (슬롯, 아이콘, 드래그&드롭 등 최소 기능)
- [ ] 커스터마이징 화면 UI와 인게임 사이 전환 흐름 정리
- [ ] 데미지 인디케이터, 히트마커, 좀비 어그로 피드백 등 추가
- [ ] 간단한 게임 루프(스폰 → 생존 → 탈출/사망) 프로토타입 구성
- [ ] 멀티플레이 HUD/인벤토리/상태 UI 동기화 확인

## Phase 12 – Polish & 포트폴리오 마무리 (11–13주차)
- [ ] 이동/전투/인터랙션 체감 폴리싱 (속도, 카메라, 애니메이션 타이밍 튜닝)
- [ ] 네트워크 최적화 (RPC/복제 빈도, Relevancy, Dormancy 튜닝)
- [ ] GAS/인벤토리/무기/AI 코드 구조 정리 및 리팩터링
- [ ] 디버그 명령/치트 추가 (좀비 스폰, 아이템 지급, 텔레포트 등)
- [ ] 대표적인 시나리오(커스터마이징 → 인게임 → 좀비/무기/인터랙션)를 녹화
- [ ] README 및 기술 문서에서 각 시스템(이동, GAS, 인벤토리, AI, 인터랙션) 정리
- [ ] 빌드/실행 가이드 및 엔진 버전/옵션 명시하여 포트폴리오용으로 정돈
